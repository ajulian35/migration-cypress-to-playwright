# Measured Improvement

## Subject

REQ-006 — Employee Search autocomplete: replacement of a fixed sleep with a condition-based wait and name-filtered locator.

---

## Before State

**File:** `playwright/pages/employee_list_page.py`

```python
def search_by_name(self, name: str):
    self.page.fill(self.NAME_INPUT, name)
    self.page.wait_for_timeout(800)          # fixed 800 ms sleep
    suggestion = self.page.locator('.oxd-autocomplete-dropdown .oxd-autocomplete-option').first
    if suggestion.is_visible():
        suggestion.click()
```

**Observed failure mode (from `failure_analysis.md`):**

When the autocomplete response arrived after 800 ms (slow network or loaded demo server), `suggestion.is_visible()` returned `False`. The `if` branch was skipped silently. The subsequent search returned all employees — the assertion `get_result_rows().count() > 0` passed because the unfiltered list was non-empty. The test passed for the wrong reason.

Additionally: even when the dropdown did appear within 800 ms, `.first` selected whatever suggestion appeared first — which on the shared demo was `"admin"`, not `"Julian"`. The name-match assertion then failed:

```
AssertionError: No directory card found containing 'Julian'
assert 0 > 0
```

**Test result before fix:** FAILED
```
FAILED tests/step_defs/req_006_steps.py::test_search_employee_by_name_returns_matching_results
AssertionError: No directory card found containing 'Julian'
```

---

## Change Applied

**File:** `playwright/pages/employee_list_page.py`

```python
def search_by_name(self, name: str):
    self.page.fill(self.NAME_INPUT, name)
    self.page.wait_for_selector('[role="listbox"] [role="option"]', timeout=5000)
    self.page.locator('[role="listbox"] [role="option"]').filter(has_text=name).first.click()
```

Two changes:

1. `wait_for_timeout(800)` → `wait_for_selector(..., timeout=5000)`: waits up to 5 seconds for the dropdown to appear; throws `TimeoutError` immediately and explicitly if it does not, rather than silently degrading.
2. `.first` → `.filter(has_text=name).first`: ensures the clicked suggestion matches the searched name, not the first item in the list (which belongs to a different employee on the shared demo).

The same fix was applied to the equivalent Cypress Page Object (`cypress/pages/EmployeeListPage.ts`):

```typescript
// Before
cy.get('[role="listbox"] [role="option"]').first().click();

// After
cy.get('[role="listbox"] [role="option"]').contains(name).click();
```

## What Got Worse

Nothing degraded. The only behavioral change is that on a genuinely slow network (>5 s autocomplete response), the test now fails fast and explicitly with a `TimeoutError` rather than silently passing with incorrect scope. That is the desired behavior — a clear failure is preferable to a false pass.

---

## Why This Matters

The original code was generated by the AI agent. The fixed sleep and unfiltered first-click are a common AI generation pattern: they work under the conditions the agent observed during exploration but do not generalize to variable network conditions or shared demo state. This is exactly the kind of output that requires human review — the code runs, the test passes, and the defect is invisible until the environment changes.
