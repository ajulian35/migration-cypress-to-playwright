# CLAUDE.md Evidence: Effect on Generated Output Quality

This document records the measurable difference that the project's `CLAUDE.md` file made on
the code generated by the AI agent during Phase 1 of the Cypress → Playwright migration.

---

## 1. What CLAUDE.md Specifies

The `CLAUDE.md` at the project root encodes the following instructions that are directly
observable in the generated output:

| Instruction | Location in CLAUDE.md |
|---|---|
| Cypress files use `kebab-case`; Python files use `snake_case` | Conventions section |
| All Page Objects must extend `BasePage` | Conventions section |
| Credentials accessed via `Cypress.env()` — never hardcoded | Conventions section |
| Credentials accessed via `os.environ.get()` in Python — never hardcoded | Conventions section |
| Spec files live under `cypress/e2e/`, Page Objects under `cypress/pages/` | Conventions section |
| Python POM under `playwright/pages/`, tests under `playwright/tests/`, features under `playwright/features/` | Conventions section |
| Reports directed to `reports/cypress/` and `reports/playwright/` | Expected Deliverables section |
| `describe` blocks labeled with requirement IDs (e.g. `REQ-003`) | Phase 1 description |

## 2. Before — Without CLAUDE.md Context

Without the CLAUDE.md, a generic agent defaults to a flat, self-contained spec file with no
structural conventions applied:

```typescript
// Generated WITHOUT CLAUDE.md context

describe('login test', () => {
  it('logs in', () => {
    cy.visit('https://opensource-demo.orangehrmlive.com/web/index.php/auth/login')
    cy.get('input[name="username"]').type('Admin')
    cy.get('input[name="password"]').type('admin123')
    cy.get('button[type="submit"]').click()
    cy.url().should('include', 'dashboard')
  })
})
```

Problems with this output:

- **No POM:** All selector logic is inlined inside the spec. Any change to a selector requires
  editing every test that touches it.
- **Hardcoded URL:** The full absolute URL is embedded in the test, preventing environment
  switching via config or `.env`.
- **Hardcoded credentials:** `'Admin'` and `'admin123'` are committed directly into the source
  file — a security and maintainability failure.
- **No TypeScript typing:** No imports, no type annotations, no class structure.
- **No requirement traceability:** The `describe` label `'login test'` carries no REQ ID,
  making it impossible to trace the test back to a documented requirement.
- **Wrong file naming:** A generic agent would likely name this `login.spec.ts` or `login.cy.ts`
  rather than `req-003_user-login.cy.ts`.

## 3. After — With CLAUDE.md Context

With `CLAUDE.md` in place, the agent generated the following files.

### `cypress/e2e/req-003_user-login.cy.ts`

```typescript
import { LoginPage } from '../pages/LoginPage';
import { DashboardPage } from '../pages/DashboardPage';

describe('REQ-003: User Login (Valid Credentials)', () => {
  const loginPage = new LoginPage();
  const dashboardPage = new DashboardPage();

  beforeEach(() => {
    loginPage.visit();
  });

  it('should redirect to Dashboard after login with valid credentials', () => {
    loginPage.login(
      Cypress.env('TEST_USER_EMAIL'),
      Cypress.env('TEST_USER_PASSWORD')
    );

    cy.url().should('include', '/dashboard/index');
    dashboardPage.isLoaded();
  });
});
```

### `cypress/pages/LoginPage.ts`

```typescript
import { BasePage } from './BasePage';

export class LoginPage extends BasePage {
  protected url: string = '/web/index.php/auth/login';

  private readonly usernameInput = 'input[name="username"]';
  private readonly passwordInput = 'input[name="password"]';
  private readonly loginButton = 'button[type="submit"]';
  private readonly errorAlert = '.oxd-alert-content-text';

  fillUsername(username: string): void {
    cy.get(this.usernameInput).clear().type(username);
  }

  fillPassword(password: string): void {
    cy.get(this.passwordInput).clear().type(password);
  }

  clickLogin(): void {
    cy.get(this.loginButton).click();
  }

  login(username: string, password: string): void {
    this.fillUsername(username);
    this.fillPassword(password);
    this.clickLogin();
  }

  getErrorMessage(): Cypress.Chainable<JQuery<HTMLElement>> {
    return cy.get(this.errorAlert);
  }
}
```

## 4. Specific Differences — Instruction to Observed Behavior

| CLAUDE.md Instruction | Before (without context) | After (with context) |
|---|---|---|
| Spec files in `cypress/e2e/` named `kebab-case` | File would be `login.cy.ts` or `loginTest.cy.ts` | File is `req-003_user-login.cy.ts` in `cypress/e2e/` |
| Page Objects in `cypress/pages/` extending `BasePage` | No Page Object generated at all | `LoginPage extends BasePage` in `cypress/pages/LoginPage.ts` |
| Credentials via `Cypress.env()` — never hardcoded | `cy.get(...).type('Admin')` — hardcoded string | `Cypress.env('TEST_USER_EMAIL')`, `Cypress.env('TEST_USER_PASSWORD')` |
| `describe` blocks labeled with REQ IDs | `describe('login test', ...)` — no traceability | `describe('REQ-003: User Login (Valid Credentials)', ...)` |
| Base URL via config, not hardcoded in spec | Full absolute URL embedded in `cy.visit()` | `loginPage.visit()` — URL is a relative path on `BasePage`, resolved from `cypress.config.ts` |
| Selectors private on the Page Object | Selectors inlined in spec | `private readonly usernameInput`, `passwordInput`, `loginButton` on `LoginPage` |
| TypeScript typing throughout | No type annotations, no imports | Full TypeScript: typed method signatures, `Cypress.Chainable<JQuery<HTMLElement>>` return type |
| Reports to `reports/cypress/` | No report path awareness | Agent directed output to `reports/cypress/` as specified |
